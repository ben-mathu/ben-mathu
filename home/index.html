RSS Feed ReaderTool

RSS Feed Reader

RSS (Really Simple Syndication) feed reader is a simple Python tool that can be used to aggregate feeds from a blog, website or podcast and saves this data in a databases. This helps to easily keep track of favorite sites while receiving customized updates of the news outlets or topics registered.

This project was built in an attempt to create a backend service and application to keep track of feeds a user would like to keep up with based on unique topics (eg. sports, politics, or titles such as those for podcast and music)

Data flow

  • User registers a feed by providing a URL of the feed.
  • Each RSS feed registered has a topic that is registered as single schedule so a scheduler is created to track updates from the feed.
  • Backend service that aggragates data from the feed and saves the data on a database for every scheduled interval.
  • A message stream is registered to track new entries and sends a notification to the user via email, sms or push notification.
  • REST APIs are used to retrieve data from the database, feeding the user details about the feed and its updates through an application.
  • The user receives feeds/updates and opens the article or navigate to their favorite browser to enjoy a good read or video.

System Requirements

Features

  • Reader

    Reader creates a simple command line application that gets inputs from the user. Accepts RSS URL, loads the downloaded xml and deserializes the response into objects which are persisted into a database.

  • Scheduling Tool

    Creates a cron job for each topic and RSS feeds to check for new post or feed. Publish messages to Apache Kafka to notify consumers of updates or new Feeds.

  • RSS Reader Application

    This application consumes the messages, receives feeds from the cron jobs by registering kafka topics. This application receives these feeds in real time.

TapCardProject

Business Cards

An open-source Android application designed to bring back contact card sharing and business card management without privacy hurdles, subscription paywalls, or third-party cloud lock-in.

Architecture & Key Components

The app uses a direct-to-database architecture consuming Room ORM with zero network overhead.

1. Data Transfer Objects (DTO)

Located in com.benatt.businesscards.data.dto:

  • VCardDto: Comprehensive model implementing java.io.Serializable, fully compliant with RFC 2426 (vCard 3.0) and RFC 6350 (vCard 4.0).
    • Identification: uid, formattedName (FN), name (N), nickname.
    • Organization: organization (ORG), title, role.
    • Contacts: phones (TEL), emails (EMAIL), addresses (ADR), websites (URL), socialProfiles (X-SOCIALPROFILE).
    • Media & Location: photoUri, logoUri, geo (coordinates), timezone.
    • Metadata: birthday, anniversary, note, categories, revision, customFields.
  • Sub-DTOs: VCardNameDto, OrganizationDto, PhoneDto, EmailDto, AddressDto, WebDto, SocialProfileDto, GeoLocationDto.
  • Enums: PhoneType, EmailType, AddressType, WebType, SocialPlatform.

2. VCard Parser & Serializer

Located in com.benatt.businesscards.data.parser:

  • VCardParser:
    • parse(inputStream: InputStream): List<VCardDto>
    • parse(file: File): List<VCardDto>
    • parse(vCardText: String): List<VCardDto>
    • parseSingle(vCardText: String): VCardDto?
    • Features: Handles multi-card .vcf streams, RFC multiline unfolding (lines indented with space/tab), escape character decoding (\,, \;, \\, \n), and property parameter parsing (TYPE=CELL,PREF, TYPE=WORK).
  • VCardSerializer:
    • serialize(card: VCardDto): String
    • serializeAll(cards: List<VCardDto>): String
    • Converts cards back into standard RFC vCard text for export or sharing.

3. Room ORM Persistence Layer

Located in com.benatt.businesscards.data.local:

  • VCardEntity (entity/VCardEntity.kt):
    • Primary Key: id: String (UUID / UID).
    • Indexed columns for fast search: formattedName, primaryPhone, primaryEmail, organization.
    • Preserves the original raw .vcf text in rawVcf for lossless export.
    • Conversion helpers: entity.toDto() and VCardEntity.fromDto(dto, rawVcf).
  • VCardTypeConverters (converter/VCardTypeConverters.kt):
    • High-performance, zero-dependency serialization for lists (phones, emails, addresses, social profiles, categories) using ASCII Record and Unit delimiters (\u001E and \u001F).
  • VCardDao (dao/VCardDao.kt):
    • CRUD: insertCard(), insertCards(), updateCard(), deleteCard(), deleteCardById().
    • Reactive Queries: getAllCards(): Flow<List<VCardEntity>>, searchCards(query): Flow<List<VCardEntity>>.
  • AppDatabase (AppDatabase.kt):
    • Singleton Room database instance configured for SQLite.

4. Direct DAO Importer

Located in com.benatt.businesscards.data.local:

  • VCardImporter:
    • dao.importAndSaveFromIntent(context, intent): Automatically inspects incoming Android Intent (from share sheet or file viewer) and saves all cards to Room.
    • dao.importAndSaveVcf(context, uri): Reads directly from a Content or File URI.
    • dao.importAndSaveVcf(inputStream): Reads directly from an input stream.
    • dao.importAndSaveVcf(vcfContent): Reads directly from a raw vCard text string.

            }
        }
    }
}

Emergency Response SystemProject

Building an Emergency Response Management System: From SOS Reporting to Real-Time Response

For a few months I have been working on an Emergency Response Management System designed to streamline how emergencies are reported, verified, assigned and managed.

The project was driven by the need for a centralised platform that connects people reporting emergencies with institutions responsible for responding to them. Rather than treating emergency reporting as an isolated action, the system provides a structured workflow that allows incidents to be tracked from submission through to resolution.

Architecture and Technology Stack

The backend was developed using Spring Boot (Java/Kotlin), with PostgreSQL as the primary database. An isolated PostgreSQL database was an important component to allow data persistence and retention during backend rebuilds. The mobile and web application was built using Flutter, providing a cross-platform interface for users to report and manage emergency incidents.

A key architectural decision was adopting a modularised monolithic architecture. The backend and the frontend is organised into distinct modules, each responsible for a specific area of the application. This provides separation of concerns and makes the source code easier to maintain, test and extend, while retaining the simplicity of a single deployable application. This was not the considered approach in the beginning, but I have since loosened up to the idea. It would make it easier to isolate a module when the need arises.

For real-time communication, the system uses WebSockets with STOMP messaging. This enables the backend to push incident notifications and status updates to connected operator dashboards without requiring continuous polling. REST APIs handle operations such as incident submission and management, while STOMP supports real-time updates.

Request Rate Limiting

Another important consideration was controlling the rate of incoming requests to protect the backend from excessive traffic and potential abuse. Request rate limiting helps prevent individual clients from overwhelming the API by restricting how many requests they can make within a specified time window.

This is particularly important in an emergency-response system, where maintaining API availability and responsiveness is essential. By introducing request limits, the system can manage traffic more predictably, reduce unnecessary server load and provide an additional layer of protection against automated abuse.

Key Capabilities

The system supports incident verification, assignment to relevant institutions, and incident status tracking. It also provides a centralised view of incidents, allowing operators to monitor and coordinate responses.

The separation between incident management and institutional assignments allows multiple institutions to participate in responding to an emergency, with each assignment tracked independently.

The project is steal "fresh". There are features still in the oven, including: SOS reporting, call and SMS reporting, speech-to-text integrations to log calls, and many more.

Lessons and Takeaways

One of the most important aspects of this project was balancing architectural structure with implementation complexity. The modular monolith provided a practical middle ground: clear module boundaries without introducing the operational overhead of microservices.

Integrating REST APIs with real-time messaging also reinforced the importance of choosing the right communication mechanism for each operation. Not every interaction needs a persistent connection, but time-sensitive updates benefit significantly from real-time delivery.

Overall, this project was an opportunity to bring together backend engineering, mobile and web development, database design and real-time communication into one cohesive system. More importantly, it provided practical experience in designing software around a real-world operational workflow rather than simply implementing isolated features.

BrainF**k Progamming Paradigm & Language Design (Forgive my language)

AI's Definition of Language design & References

Language design is the process of defining the syntax, semantics, and rules of a communication system—whether you are building a custom programming language, a domain-specific scripting tool, or a brand's visual identity. It focuses on creating intuitive, efficient, and scalable rules that bridge human thought and expression with a desired output.

https://cs.lmu.edu/~ray/notes/languagedesignnotes/ This second reference does not really align with this programming language :D Design Is [Language] – Why Words Matter

Anyway, I think I'll send you to Wikipedia Brainf**k to read about this programming language yourself, and try out the problem at Codewars. Once you have read through, you will discover a few instructions, which are not to difficult to understand, but the part I struggled to understand in the Codewars problem was the input. i know it clearly indicates 8-bit unsigned integer (0–255) in the Wikipedia, but wueh! This knocked me out. So from now on, know this the input and output of this programming language is an 8-bit unsigned array. Okay?

The instructions are defined as follows:

> Increment the data pointer by one (to point to the next cell to the right).

< Decrement the data pointer by one (to point to the next cell to the left). Undefined if at 0.

+ Increment the byte at the data pointer by one modulo 256.

- Decrement the byte at the data pointer by one modulo 256.

. Output the byte at the data pointer.

, Accept one byte of input, storing its value in the byte at the data pointer.

[ If the byte at the data pointer is zero, then instead of moving the instruction pointer forward to the next command, jump it forward to the command after the matching ] command.

] If the byte at the data pointer is nonzero, then instead of moving the instruction pointer forward to the next command, jump it back to the command after the matching [ command.

The above instructions, as I said are simple. I will try and explain how my simple mind understood this. We will start with:

>

Picture this. You have an unbounded byte array (rem. 8-bit unsigned array). By unbounded I mean an infinite length, size, of the array.

...some implementations allocate a finite array of cells (commonly at least 30 000 bytes)

https://en.wikipedia.org/wiki/Brainfuck

If you have a pointer pointing to the leftmost element in this array, lets say zero (0), this command simply increments the pointer by one so it points to index 1. capisci?

<

The Vice versa of the > command is the < command. Which should decrement the pointer by one so that it points to a previous memory allocation. By Interchanging terms here, I hope it helps you understand where some of these ideas come from and how some languages like C are designed. Moving on.

+

This commands should add one to the data stored at the memory allocation at the pointer. A concept of wrapping is introduced with this command. Say you have byte equal to 255, if you add one to this data it should evaluate to 256, but since the data is capped at 8-bit, the data is wrapped around to 0. I hope that is simple enough. I feel like the explanation might have not helped.

-

This command should subtract one from the data stored at the pointer and wraps around to 255 if the data stored reaches 0.

.

This commands should output the data at the data pointer. This is similar to the standard output from languages such as C/C++ (cout) statements.

,

This command should take an input and store it at the data pointer. This is similar to input statement such as: input, from python; System.in, from Java; cin, from C/C++.

[

This command is interesting. It initiates a looping block and first should check if the byte, data, at the data pointer is 0, if it is it skips the instruction pointer, the pointer of this instruction, to the last equivalent/matching ']' command, otherwise the next instruction after is executed. An instruction pointer is similar to a data pointer, but instead of pointing to a data allocation it points to a point in the instruction set, where an instruction set is a strategic combination of instructions (listed above) that aims to achieve some objective.

]

This command terminates the loop. It checks if the byte at the data pointer is a nonzero. If it is, it jumps the instruction pointer back to an equivalent/matching '[' command, otherwise, it move the instruction pointer forward to the next instruction.

As simple as this might be I feel I might have butchered at explaining and trying to create a mental image of how to interpret this language. Programming languages, like any language, are meant to interpret the meaning or thought from one language to another. For instance, I interpreted BrainF**k (sorry fot the language :D) using java, which I have deliberately not included the Java interpreter here so you can write it yourself, if I got you interested. if you wanted, you could build an interpreter for JavaScript using Java or C or Python. Someone listed some interpreters at A list of JavaScript engines, runtimes, interpreters.
